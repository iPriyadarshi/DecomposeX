Applications

What the factorization is good for

L, D and U are not the goal. They are a reusable summary of one elimination, and once you have them, six different questions about the matrix become cheap.

Solving A·x = b

This is the reason the factorization exists. Substituting A = LDU into Ax = b gives L(D(Ux)) = b, and peeling off one factor at a time turns one hard problem into three easy ones:

The three passes
  1. Forward substitution. Solve L·y = b going downwards. L is unit lower triangular, so this needs no division at all.
  2. Diagonal scaling. Solve D·z = y. One division per entry: zk = yk / dk.
  3. Back substitution. Solve U·x = z going upwards. U is unit upper triangular, so again no division.

Every division in the whole process is concentrated in step 2, against the pivots. That is a real structural advantage: the only place the computation can break is the one place you already know to check.

With a permutation

If the factorization needed row swaps then the identity is P·A = L·D·U, so the system to solve is L·D·U·x = P·b. Permute the right-hand side first, using the same row order. The solution x itself is not permuted; only b is.

Many right-hand sides

The economics are what make factorization worth the trouble. Elimination costs about n³/3 operations and depends only on A. Each substitution pass costs about n²/2, so a complete solve after factorizing costs about n².

Approach 1 system k systems n = 500, k = 100
Fresh elimination each time n³/3 k·n³/3 ≈ 4.2 × 109
Factor once, then substitute n³/3 + n² n³/3 + k·n² ≈ 6.7 × 107

Leading terms only, counting multiply–add pairs. At these sizes reusing the factorization is roughly sixty times less work, and the gap widens with k.

This pattern is everywhere. An implicit time-stepping scheme solves against the same matrix at every step. Newton's method re-solves with the same Jacobian across several iterations. A finite-element model applies many load cases to one stiffness matrix. In all of them the matrix is factored once and the factors are kept.

Determinants

Expanding a determinant by minors costs O(n!) operations: for n = 20 that is longer than the age of the universe on any hardware. The factorization reduces it to a product:

det A = (−1)s · d1 d2 ⋯ dn

where s is the number of row swaps. It follows from taking determinants of PA = LDU: both triangular factors have determinant 1, and det P = (−1)s. So the determinant costs n multiplications on top of the elimination you already did: a reduction from factorial to cubic.

Inverses

The inverse is n solves in disguise. Column j of A⁻¹ is the solution of A·x = ej, where ej is the j-th column of the identity. Run the three passes once per column, reusing the same factorization, and assemble the results:

A−1 = [ x1 │ x2 │ ⋯ │ xn ],    where A xj = ej.

Total cost ~n³: three times the factorization, not n times it.

But usually, do not

If your actual goal is to solve Ax = b, computing A⁻¹ and then multiplying is both slower and less accurate than substituting directly. Forming the inverse costs about three times as much as one solve, and the matrix product adds its own rounding. A⁻¹b is a statement about mathematics; solve is the instruction you want in code.

Rank, singularity and consistency

The pivots answer structural questions at a glance:

  • Singularity. A is invertible exactly when every dk ≠ 0. A single zero pivot means det A = 0.
  • Rank. The number of non-zero pivots in a fully reduced form is the rank: the number of independent rows.
  • Consistency. After forward substitution, a row where dk = 0 but yk ≠ 0 reads 0 = yk: the system has no solution. If yk = 0 as well, that variable is free and there are infinitely many solutions.

The calculator reports all three, and its Solve tab distinguishes a unique solution from an inconsistent system and from an under-determined one.

Testing definiteness

For a symmetric matrix, the signs of the pivots classify the quadratic form q(x) = xᵀAx completely, and getting them costs one factorization rather than an eigenvalue computation.

Pivot signsClassificationMeaning for q(x) = xᵀAx
all > 0Positive definiteq(x) > 0 for every x ≠ 0: a strict minimum
all < 0Negative definiteq(x) < 0 for every x ≠ 0: a strict maximum
mixed signsIndefiniteq takes both signs: a saddle point
some zero, rest one signSemi-definiteq ≥ 0 (or ≤ 0), vanishing on a subspace

The count of positive, negative and zero pivots is called the signature of the form, and Sylvester's law of inertia guarantees it does not depend on how you got there. This is why optimisation codes factor the Hessian: a positive-definite factorization confirms a descent direction, and a failure mid-way tells you the step needs modifying.

The route to Cholesky

For symmetric positive-definite matrices, LDLᵀ and Cholesky are the same factorization written two ways. From A = LDLᵀ with every dk > 0, set R = L·D1/2 and you have A = RRᵀ.

That last row is why this site computes LDLᵀ exactly and shows the Cholesky factor as the one decimal approximation anywhere in it. It is also why LDLᵀ is preferred in practice whenever a matrix might not be positive definite: the factorization simply reports a negative pivot instead of failing.

Where you meet this in practice

Circuit analysis

Nodal analysis produces a symmetric positive-definite conductance matrix. SPICE-style simulators factor it once per operating point and substitute for each time step.

Structural engineering

A finite-element stiffness matrix is symmetric and usually positive definite. One factorization serves every load case, which is exactly the many-right-hand-sides pattern.

Least squares

The normal equations AᵀA x = Aᵀb have a symmetric positive-definite matrix, so LDLᵀ or Cholesky solves them, though QR on A directly is better conditioned.

Optimisation

Newton and interior-point methods factor a Hessian or KKT matrix each iteration. The pivot signs double as the second-order test.

Kalman filtering

Covariance matrices are symmetric positive definite; propagating their LDLᵀ factors instead of the matrices keeps them from losing definiteness to rounding.

Computer algebra

Over the rationals, fraction-free variants such as Bareiss elimination keep entries from blowing up: the same problem this site's arbitrary-precision arithmetic solves by brute force.
