How this site is built

DecomposeX is a static site with no dependencies, no build step and no tracking. It runs from the file system as happily as from a web server.

Exact arithmetic

The design decision that shapes everything else: no value anywhere in this site is a floating-point number. Every entry, multiplier, pivot and determinant is an exact ratio of two arbitrary-precision integers.

js/fraction.js
class Fraction {
  n: BigInt     // numerator, carries the sign
  d: BigInt     // denominator, always > 0

  // invariants, established in the constructor and never broken
  //   d > 0
  //   gcd(|n|, d) = 1  (always in lowest terms)
}

Because every instance is reduced and frozen at construction, two fractions are equal exactly when their numerators and denominators match. That makes isZero() a genuine test rather than a tolerance, which is what allows the factorization to handle zero pivots correctly instead of dividing by something that is merely small.

What exactness buys, concretely
  • 0.1 + 0.2 equals 0.3.
  • 1/3 added three times equals exactly 1.
  • A singular matrix has a determinant of 0, not 1.9e-16.
  • Nine-digit entries stay exact where doubles have already lost digits.
  • Results display as 3/4 rather than 0.75000000001.

The cost is growth: numerators and denominators get longer as elimination proceeds, and for a 10×10 matrix of awkward fractions they can reach dozens of digits. Computer-algebra systems avoid this with fraction-free methods such as Bareiss elimination. For a teaching tool at these sizes, plain rational arithmetic is simpler to read and fast enough to feel instant.

How numbers are displayed

Fractions are shown exactly. Decimals are truncated, not rounded, with a trailing … marking digits that continue, so 9999/10000 at three places shows as 0.999… and never as a misleading 1. A separate properly-rounded formatter is used for exports.

Project structure

FileResponsibility
js/fraction.jsExact rational arithmetic on BigInt: parsing, the four operations, comparison and formatting.

css/main.cssOne design system: tokens, components, light and dark palettes, print styles.
js/<page>.jsOne file per page for that page's interactive parts.

The split that matters is between ldu.js and everything visual. The factorization code has no reference to the DOM, which is why the same functions run in the calculator, in every figure on the Theory and Algorithm pages, in the examples gallery, and in the test suite.

How correctness is checked

Three layers, all independent of the factorization code itself:

  1. Self-verification at runtime. Every factorization recomputes L·D·U and compares it entry by entry with P·A. The result is shown on the calculator's Verification tab, and a failure would be reported rather than hidden. The same check runs behind every figure on the site.
  2. Cross-checks between independent computations. The determinant is computed twice, once as the signed product of the pivots, once by a separate elimination, and rank is computed by a different row-reduction that advances rows and columns independently. Leading principal minors give a third, theoretical prediction of whether a permutation will be needed.
  3. A test suite. 151 assertions, run with node tests/run.js and needing no dependencies. They cover fraction parsing and formatting, the known-answer 3×3 case, matrices needing permutations, singular matrices that still factor, the matrix that has no factorization, symmetric and positive-definite detection, edge sizes from 1×1 up, big-integer exactness, solving, inconsistency detection and inversion; plus randomised runs over several hundred matrices asserting that the factors always multiply back and that the minor test always predicts the permutation.

Every claim in the example notes is asserted too: each entry records the outcome it is chosen to illustrate, and the suite fails if the prose and the algorithm ever disagree.

What this rewrite fixed

The original version of this project was a single page with a short script. It computed the right answer for well-behaved matrices and silently wrong answers for everything else. The specific defects:

ProblemWhat happenedNow
Division by a zero pivot No check before dividing, so a zero pivot produced Infinity and then NaN through the rest of the matrix. The pivot is tested exactly; a row swap is applied, or the failure is explained.
No row permutation Matrices as simple as [[0,1],[1,0]], perfectly invertible, returned garbage. Row swaps are tracked in P and the result is reported as P·A = L·D·U.
Floating-point drift Errors accumulated through elimination and were hidden by toFixed(2), so a mathematically exact 0 could print as -0.00. Exact rational arithmetic throughout; fractions display as fractions.
No verification Nothing ever checked that the factors multiplied back to A. Checked on every run and shown.
No diagnostics Singular and rank-deficient matrices were indistinguishable from well-behaved ones. Determinant, rank, minors, symmetry and definiteness all reported.
Unvalidated input An empty cell parsed as NaN and poisoned the result with no warning. Each entry is validated as it is typed, with the offending cell marked.
Misleading steps Snapshots of L and U were shown, but the elimination updates to A never were, so the steps did not explain the result. Each stage shows its multipliers, its row operations and the resulting matrix.

Accessibility and browser support

  • Every interactive control is a real <button>, <input> or <select>, reachable and operable by keyboard.
  • Matrices carry an aria-label that reads out row by row, since a grid of numbers is meaningless to a screen reader otherwise.
  • The matrix editor supports arrow-key navigation, Enter to factorize, and pasting a whole matrix into any cell.
  • Colour is never the only signal: every status also carries text.
  • Light and dark themes both meet WCAG AA contrast for body text; the theme follows the operating system until you choose one.
  • prefers-reduced-motion is respected: all animation is disabled.
  • Print styles drop the navigation and controls so a factorization prints as a clean page.

The only hard requirement is BigInt, which every browser has supported since 2018. Chrome 67, Firefox 68, Safari 14, Edge 79.

Further reading

Gilbert Strang, Introduction to Linear Algebra
Chapter 2 develops elimination into LU and then LDU, and is the clearest first exposition of why the factors are what they are.
Trefethen & Bau, Numerical Linear Algebra
Lectures 20–23 cover LU with pivoting and the stability analysis that motivates it. Essential if you care about floating-point behaviour.
Golub & Van Loan, Matrix Computations
The reference. Chapter 3 treats general linear systems; Chapter 4 covers LDLᵀ and Cholesky for symmetric matrices.
Higham, Accuracy and Stability of Numerical Algorithms
Chapter 9 is the definitive account of error analysis for LU factorization, where the tolerance heuristics come from and when they fail.
Horn & Johnson, Matrix Analysis
Section 3.5 gives the existence and uniqueness results in full generality, including the singular cases this site handles.

The project

DecomposeX is open source. Corrections to the mathematics are especially welcome. If you find a matrix where the factorization or a diagnostic is wrong, that is a bug worth reporting, and the matrix itself is the whole report.

Running it locally

terminal
git clone https://github.com/iPriyadarshi/DecomposeX.git
cd DecomposeX

# open index.html directly; there is no build step
start index.html        # Windows
open index.html         # macOS
xdg-open index.html     # Linux

Everything works over file://. The only network request is the web font, and the design falls back to system fonts without it.
